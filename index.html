5 Exit ticket

A user interface (UI) is the part of a digital product that a person sees and uses. It includes screens, menus, buttons, forms, icons, labels and navigation.

User experience (UX) is the overall experience a person has while using the product. A product can look attractive but still deliver poor UX if it is confusing, slow or inaccessible.

UI asks

What does the user see, touch, click, type or hear?

UX asks

Can the user complete the task easily, confidently and efficiently?

Enterprise system

A system that helps an organisation collect, store, process and communicate information.

3 min Exit ticket

Every information system can be examined as a flow of data.

Input

Data entered or collected, such as a form response, image, barcode or date.

Process

What the system does to the data, such as calculating, validating or filtering.

Storage

Where data is kept, such as Google Sheets or cloud storage.

Transmission

How data moves between the user, AppSheet, Google services and other users.

Output

Information displayed or produced, such as a chart, confirmation or dashboard.

10 min Guided learning

3 min Exit ticket

Design choices can affect individuals and communities. Responsible designers consider privacy, consent, fairness, accessibility, copyright, data ownership and cybersecurity.

Privacy

Collect only data that is genuinely needed. Avoid unnecessary personally identifying information.

Consent

Users should understand what is collected and why.

Fairness

Features and language should not exclude or disadvantage groups.

Ownership

Identify who owns the data and who may access, edit, share or delete it.

What are terms of use and EULAs?

Terms of use explain the rules for using a service. An End User Licence Agreement explains how software may be used. These documents may describe data collection, account rules, ownership of uploaded content, limits of liability and reasons an account can be suspended.

Week 3 · Lesson 7

Inclusive communication and accessibility

AccessibilityDiverse audiencesCommunication

5 min Do now: accessibility barrier

Imagine a user has low vision, limited English, colour-vision deficiency or limited hand movement. Identify one barrier each user might face in a poorly designed app.

10 min Guided learning

Review readable, perceivable, operable and respectful design. Notice that accessibility is not an extra feature added at the end; it shapes labels, layout, colour, navigation and testing.

15 min Redesign challenge

Choose a confusing form or screen. Describe how you would improve labels, field order, instructions, error messages and colour use.

7 min Audience review

Explain how your app communicates effectively with two different audience groups.

3 min Exit ticket

Communication choices influence whether an audience can understand, trust and use a product. Designers should consider people of different ages, genders, cultures, language backgrounds and abilities.

Readable

Clear labels, plain language, sufficient text size and useful spacing.

Perceivable

Do not rely on colour alone. Add text, icons, patterns or labels.

Operable

Logical navigation, large touch targets and predictable controls.

Respectful

Avoid stereotypes and seek feedback from the people represented.

When designing for Aboriginal and Torres Strait Islander Peoples, avoid treating cultures as one single group. Use respectful language, recognise diversity between communities and do not use cultural images, stories or knowledge without permission.

Compression, file formats and media choices

LossyLosslessPerformance

5 min Do now: format match

Match these files to a suitable format: logo with transparency, photograph, document bundle, spoken audio.

10 min Guided learning

Compare lossy and lossless compression. Consider quality, speed, storage, transmission and whether the original information must be recovered exactly.

15 min File-size investigation

Choose one image and compare its size before and after resizing or compression. Record dimensions, file size and visible quality.

7 min Project media plan

List the media your app will use and choose suitable formats for each.

3 min Exit ticket

Compression reduces file size. Smaller files usually load and transmit faster, but the chosen method affects quality.

Lossless compression

No information is permanently removed. The original can be reconstructed. Useful when accuracy matters.

Lossy compression

Some information is permanently removed to create a smaller file. Useful for photographs, audio or video when a small quality reduction is acceptable.

An entity is something the system stores information about. An attribute is a property of that entity. A record is one instance of an entity.

Entity

Player

Attributes

PlayerID, name, position, email

Record

One row describing one player

Primary key

A unique value that identifies each record

Your assessment requires at least three connected tables. Connections are normally created using a key in one table and a reference field in another.

Design your table structure

Security is not simply “adding a password”. It involves minimising data, controlling access, selecting appropriate sharing settings and explaining how data moves and is protected.

Data minimisation

Collect the least amount of personal information needed.

Least privilege

Give each user only the access required for their role.

Secure sharing

Do not make a school app public unless specifically approved.

Mock data

Use fictional records for assessment testing unless your teacher approves real data collection.

Glossary

Accessibility
Designing a product so people with a range of needs and abilities can use it.
Attribute
A property or field used to describe an entity.
Data validation
A rule that checks whether entered data is acceptable.
Entity
A person, object, place, event or concept about which data is stored.
Functional requirement
A specific action or capability the system must provide.
Information architecture
The structure, organisation, labels and navigation used to make information findable.
Iteration
Repeating design, development, testing and improvement.
Lossless compression
Compression that preserves all original information.
Lossy compression
Compression that removes some information to reduce file size.
Non-functional requirement
A quality requirement such as usability, accessibility, security or performance.
Personally identifying information (PII)
Information that can identify a particular person.
Primary key
A field containing a unique value for each record.
Reference field
A field used to connect a record to a record in another table.
UI
The controls and visual or interactive elements through which a user operates a product.
Use case
A description of how a user interacts with a system to achieve a goal.
UX
The complete experience a user has while using a product or service.
